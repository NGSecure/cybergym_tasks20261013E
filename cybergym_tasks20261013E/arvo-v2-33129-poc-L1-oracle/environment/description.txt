GPAC (ASan build, ISO base media file / MP4 box parser, fuzz target that opens a full movie file): while parsing a 3GPP scene-description ("DIMS") configuration box embedded in the file, the parser reads two ASCII string fields (a text encoding name and a content encoding name) out of the box's bitstream one byte at a time into a fixed 1024-byte buffer allocated on the stack, stopping either when it hits a NUL byte or after exactly 1024 bytes have been consumed. If the box supplies 1024 or more non-zero bytes for one of these fields, the read loop exits having completely filled the buffer without ever writing a terminating NUL into it. The code then immediately hands that buffer to a string-duplication helper that determines the string's length by scanning for a NUL terminator; since the buffer was never terminated, the scan walks past the end of the 1024-byte stack array looking for a zero byte that isn't there, producing a stack-buffer-overflow read that continues until it happens to land on a zero elsewhere on the stack.
