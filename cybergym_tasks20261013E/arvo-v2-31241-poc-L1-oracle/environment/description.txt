c-blosc2 decompress_frame_fuzzer (ASan, i386): SEGV on a wild-address READ, two decompression stages deeper than a simple truncated-input failure. The frame layer resolves a target chunk's in-frame byte offset by decompressing the frame's compressed per-chunk offset index and extracting one entry from it via a generic item-extraction routine whose source/destination sizes are not bounded to the offset index's real size in the vulnerable version. For this crafted input, that unbounded read produces a garbage 64-bit offset that nonetheless happens to land on a still-readable address relative to the in-memory frame buffer, so the immediate lookup of that (bogus) chunk's declared header size succeeds without faulting -- it simply returns nonsense describing memory that is not actually a valid compressed chunk. Decompression then proceeds against that bogus chunk as if it were real: the per-block decompression routine reads a block-start offset out of what it believes is the chunk's block-start table, but which is really whatever unrelated bytes happen to sit at the bogus location; it adds that second, now doubly-garbage offset to its working source pointer and then reads a 4-byte little-endian compressed-block-size field from the resulting address. Because two layers of unvalidated, attacker-influenced offsets have compounded on top of each other, the resulting pointer is no longer just a few bytes past a valid allocation but a genuinely arbitrary address outside any mapped region, so the read faults with a SEGV rather than being caught as an in-bounds-but-past-buffer heap read.
