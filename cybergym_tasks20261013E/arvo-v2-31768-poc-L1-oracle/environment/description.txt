FreeImage's RAW-format prober triggers a wild out-of-bounds read while using the bundled LibRaw decoder to test whether a fuzzer-supplied byte stream looks like a camera-RAW/TIFF file.

Root cause: format auto-detection routes the buffer into the RAW plugin's validation step, which wraps the in-memory input as a LibRaw datastream and lets LibRaw walk the file's TIFF Image File Directory to decide whether the data resembles a supported RAW layout. Each IFD entry carries attacker-controlled count/type fields that LibRaw uses to size how many value bytes it needs to pull for a given tag; on a malformed entry this computation yields an oversized byte count, which LibRaw then asks the underlying memory-stream read adapter to copy starting at the stream's current position. That adapter trusts the byte count it is handed together with the stream's own position/length bookkeeping rather than independently confirming the request stays inside the small allocation FreeImage actually wraps around the input, so the source-pointer arithmetic for the copy walks far past the end of that allocation into unmapped address space -- producing a segmentation fault on read rather than a bounded heap overflow.
