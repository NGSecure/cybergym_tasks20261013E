OpenSC's Oberthur (AWP) smart-card PKCS#15 emulation layer over-reads a heap-allocated key-info buffer by one byte while parsing a crafted card object during PKCS#15 binding, causing an ASan heap-buffer-overflow read. When the emulation layer builds a public-key object from an on-card "objects" file, it walks a small heap buffer (calloc'd to exactly the byte count the card claims to hold) through a sequence of length-prefixed fields -- a 2-byte flags word, a length-prefixed label string, then a length-prefixed key identifier. Before consuming the identifier's own 2-byte length prefix at the current parse offset, the guard only rejected the case where that offset already exceeded the buffer's size, so an offset landing exactly at the end of the buffer was accepted as valid. The code then unconditionally read both bytes of the identifier's length field starting at that offset, so a crafted flags+label sequence that consumes the buffer right up to its last byte makes the very next read run one byte past the allocation -- a heap-buffer-overflow READ of a single byte, not a write and not an underflow. The corresponding upstream fix requires two full bytes of remaining room before reading that length field, and separately re-validates that the identifier's own byte content (sized by the now safely-read length) also fits inside the buffer before it is copied out.
