tmux (ASan build): feeding the terminal input parser an OSC 11 (set background colour) sequence whose colour argument is not a recognized rgb:/#/cmyk:/cmy: form -- and consists of, or is prefixed by, enough space characters -- causes a heap-buffer-overflow read while trimming whitespace from the argument before treating it as a colour name by that final by-name fallback path. Root cause: the fallback's leading-space skip advances the string pointer `p` forward (`while (*p == ' ') p++;`) without shrinking `len`, which was computed once up front as the full length of the original, untrimmed string. The following trailing-space trim then walks backward from the byte at offset `len - 1` counted from `p`, but because `len` still reflects the pre-trim length while `p` has already moved forward by the number of skipped leading spaces, that backward-indexed offset overshoots the buffer's last valid byte by exactly that many bytes. When the input string is packed close enough to the end of its heap allocation (as it is here, in the fixed-size OSC input buffer), that overshoot reads past the allocation into adjacent redzone memory.
