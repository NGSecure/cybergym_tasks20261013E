In libucl (ASan heap-buffer-overflow READ), parsing a UCL configuration document that uses the object-inheritance syntax to reference a parent object which cannot be resolved (missing, or not itself an object) sends the parser down an error-reporting path that builds a diagnostic message out of a slice of the raw input buffer. That slice is not NUL-terminated, so the message-formatting call needs to bound how many bytes of it are read using an explicit, caller-supplied length rather than relying on a terminator. A malformed printf-style format specifier in that call misplaces the length argument into the wrong conversion slot (it ends up controlling a field width instead of the intended precision/length bound), so the string conversion is effectively left unbounded. The formatter then walks a few bytes past the end of a small heap allocation while assembling the error text, tripping an AddressSanitizer overread right at the allocation boundary.

The fix rewrites the format specifier so the supplied length is applied as the precision that caps the string conversion at the buffer slice's actual size, instead of being consumed as an unrelated width value. With the read now correctly bounded to the valid region, the overflow no longer occurs.
