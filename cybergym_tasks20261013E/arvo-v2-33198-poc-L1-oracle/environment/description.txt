FreeImage (ASan build, load_from_memory_fuzzer target): the harness hands an attacker-controlled in-memory buffer straight to FreeImage's file-type sniffer. For content that resembles a RAW camera file, the sniffer's validation path calls into FreeImage's bundled LibRaw sub-library to open/inspect the buffer before any real decoder is ever chosen. LibRaw is not reading from a real file descriptor here -- its buffered-read requests go through a small adapter that turns each request into a callback against FreeImage's own memory-stream reader, which resolves it into a raw byte-copy straight out of the original in-memory buffer the fuzzer supplied. The crash is reached through LibRaw's generic TIFF-directory walker rather than EXIF/GPS parsing: a malformed TIFF image file directory contains a sub-directory pointer that sends the walker back into itself, and parsing recurses several sub-directories deep before it reaches a timestamp-style tag whose value is fetched through that same buffered-read adapter. As with a sibling crash reached via EXIF parsing in this same fuzz target, the byte offset and length used for that read are derived from attacker-controlled fields inside the raw file and are never checked against how many bytes of the input buffer actually remain -- so the adapter's byte-copy lands on a wild, far-out-of-range address and the process dies with SIGSEGV. Root cause: the same missing bounds check in the memory-stream read callback, reached this time by repeated image-file-directory recursion in the generic TIFF walker instead of a single EXIF GPS/maker-note sub-block.
