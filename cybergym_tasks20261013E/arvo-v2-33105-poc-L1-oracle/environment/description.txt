Qt Core (ASan build): parsing a crafted date/time string with QDateTime::fromString causes a 4-byte heap-buffer-overflow read while resolving a time zone whose daylight-saving transition rules are supplied in POSIX TZ form. To evaluate a transition date, the code takes the rule's date field in the "Mm.w.d" month/week/day-of-week form and splits it on '.', assuming it yields three components, then reads the second and third components and converts them to integers. Root cause: the number of components the split actually produced is never checked before indexing, so when the attacker supplies an "M"-form date rule with fewer than three dot-separated fields, the code indexes past the end of the split result's element list; that out-of-bounds slot sits just beyond the list's heap allocation, and reading the stored byte-array element's data pointer there is the small out-of-bounds over-read AddressSanitizer reports. The fix validates rule structure up front -- requiring at least three components for the month/week/day form before any is used, bounds-checking the plain and Julian day-of-year forms, and rejecting malformed transition rules whose parts are missing or empty -- so the runaway index can never be formed.
