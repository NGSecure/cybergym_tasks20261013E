A bug in matio (ASan heap-buffer-overflow write of 4 bytes) occurs when reading a MATLAB v7.3 (HDF5-based) .mat file: while iterating group links to fetch a member's metadata, the HDF5 metadata-cache loader for that object computes an implausibly small allocation size from the corrupted file (down to a single byte) and then copies a fixed-size chunk of already-read header bytes into that undersized buffer, writing past the end of the 1-byte heap allocation.
