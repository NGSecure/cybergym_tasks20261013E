PCL's PLY point-cloud parsing fuzz target (ASan build): after the per-vertex data section of a PLY file has been fully parsed into an in-memory point cloud buffer, a later fixup pass rebuilds a "valid points only" output buffer by, for each output row, copying one point-worth of bytes from the previously populated buffer at a source offset derived by multiplying an index by the per-point stride. That index is not the output row counter itself but a value pulled straight out of an auxiliary per-row table the file also supplies, and it is never checked against how many vertices were actually parsed into the buffer. A file that supplies a wildly out-of-range value in that auxiliary table makes the fixup pass compute a source offset far beyond the populated buffer's end, so the point-sized copy fetches far past the buffer -- a multi-byte heap out-of-bounds access caught by the allocator's guard region, well past the buffer's tail.
