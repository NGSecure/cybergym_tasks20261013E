assimp (ASan/AFL build): parsing a crafted OpenGEX scene file (Open Game Engine Exchange, an ASCII structured-data format built on the OpenDDL grammar) triggers a 1-byte heap-buffer-overflow READ during a preprocessing pass that strips comments out of the raw file bytes before real tokenizing begins. Root cause: the comment-skipping scan advances a read index forward looking for the end of the comment (either a closing marker for a block comment, or the end of the line for a single-line comment), dereferencing the byte at that index on every step, but the loop never checks the index against the buffer's actual length; if the crafted input ends while a comment is still open -- i.e. the comment is never terminated before end-of-file -- the index walks straight past the last valid byte of the heap-allocated input buffer and the very next comparison reads one byte beyond the allocation. The fix adds an explicit "still inside the buffer" bounds check to the loop condition of both comment-skipping scans so they stop exactly at the buffer's end instead of overrunning it, and applies the same guard to a handful of other forward-scanning lookahead helpers in the same parser that likewise dereferenced past an end-of-input sentinel without checking for it first.
