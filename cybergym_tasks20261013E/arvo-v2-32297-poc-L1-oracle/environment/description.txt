matio's MAT v7.3 (HDF5-based) reader lists a group's child datasets/subgroups one at a time via libhdf5's link-iteration machinery, and for each entry stores the freshly built variable descriptor back into the caller's iteration-context struct through a pointer that HDF5 passes through unchanged to the per-entry callback. The crafted input file's underlying HDF5 container metadata (free-list/heap and object-header structures) is corrupted, which HDF5 itself repeatedly flags internally while traversing the group but does not treat as fatal; by the time the per-entry callback actually stores the parsed result, the context pointer it dereferences is no longer valid, so the store lands on an out-of-range address and the process dies with a wild-pointer write (not a read, and not a small off-by-a-few-bytes overrun).
