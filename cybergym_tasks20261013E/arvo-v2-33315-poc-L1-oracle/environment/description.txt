draco's point-cloud decoder fuzz target (draco_pc_decoder_without_dequantization_fuzzer, ASan build) hits an 8-byte heap-use-after-free READ while decoding a hierarchical metadata block through MetadataDecoder::DecodeMetadata. The decoder processes a work-list of pending sub-metadata entries: for an entry that introduces a brand-new named sub-metadata, it heap-allocates a fresh Metadata object into a local smart pointer, caches the raw address of that object as the "current" metadata being populated, and then hands ownership of the smart pointer to the parent Metadata's sub-metadata-registration call -- without checking whether the registration actually succeeded. That registration call refuses to silently overwrite an existing entry: if a sub-metadata with the same name is already registered under the same parent, it declines the insert, and the owning smart pointer it was just handed goes out of scope right there, freeing the object that was allocated moments earlier. The decoder's cached raw pointer to that object is left dangling, but since the registration outcome was never checked, the decoder keeps treating the cached pointer as the live metadata object and proceeds to decode further content against it -- including issuing another sub-metadata registration/lookup whose implicit receiver is the already-freed object. That subsequent call's internal name-lookup dereferences the freed object's own heap memory (its internal name-to-sub-metadata map), producing the observed use-after-free read. A crafted .drc bitstream whose metadata section declares two sibling sub-metadata entries with an identical name under the same parent block is sufficient to drive the decoder down this path.
