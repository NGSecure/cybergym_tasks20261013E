LibRaw's Sony maker-note parser (MSan build): while parsing a Sony lens-spec maker-note field inside a crafted RAW/TIFF file, the code trusts the field's declared byte count to size and fill a freshly allocated scratch buffer, but never verifies that the underlying read actually supplied that many bytes from the (possibly truncated) input stream. Root cause: when the stream runs out early, the unread tail of that heap buffer is left holding whatever the allocator handed back rather than real file data, and a subsequent byte-by-byte nibble-range sanity check on the buffer's contents (followed by numeric field conversions derived from the same bytes) treats that never-written memory as valid lens data, so the sanitizer flags the read as a use of an uninitialized value rather than an out-of-bounds one.
