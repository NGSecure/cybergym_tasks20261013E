PCL's PLY point-cloud parsing fuzz target (ASan build): while walking the per-vertex data section of a PLY file, a callback that stores an incoming 8-bit color-channel value writes 4 raw bytes into a byte buffer that backs the output point cloud, at an offset derived by multiplying a running vertex counter by a per-point stride and adding a running within-vertex byte cursor. Neither the stride nor the cursor is checked against how large the destination buffer was actually allocated to be, so a header that declares more or larger properties than the buffer was sized for lets the cursor run past the end of the allocation; the very next color value gets stored one byte past the buffer's end, a heap out-of-bounds write caught immediately by the allocator's guard region.
