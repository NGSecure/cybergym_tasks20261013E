wasm3 evaluates a module's constant initializer expressions -- such as an element segment's table offset -- by running them through the same general-purpose bytecode compiler used for real function bodies, without restricting which opcodes may legally appear in that constant-expression context. If a crafted module places a branch-table instruction inside such an offset expression, the compiler accepts and emits it, which drives the branch-table code path to request a fresh block of compiled-code storage sized to hold the table's case entries. Because this offset-expression compilation runs against a temporary, stripped-down compilation state rather than the fully set-up per-function compilation state that branch-table emission normally assumes it has, the size computed for that storage block ends up far smaller than what the branch table actually needs -- observed here as an allocation of essentially a single byte. The subsequent writes of the table's case-target entries then land well past the end of that undersized heap block, and AddressSanitizer reports the resulting out-of-bounds write as a heap-buffer-overflow.
