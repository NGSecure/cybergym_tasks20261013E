A wild-pointer read (ASan SEGV) fires while tearing down a partially-parsed item-location box from a malformed/truncated MP4-family file, during the cleanup that runs after the box parser gives up on the file. The parser's main loop allocates one location-entry record per declared item using a plain, non-zero-initializing heap allocation, and links that freshly allocated record into the box's entry list immediately -- before most of the record's fields have been filled in. Only several reads later in the same loop iteration (after the entry's id, construction method, data-reference index and base offset have all been decoded) does the parser set up that entry's own sub-list handle, which is meant to track child location extents. Between those two points sit several remaining-size bounds checks against the box's declared byte budget; on a short/truncated input, one of these checks can fail first, and the parser aborts the whole read with an error right there, never reaching the sub-list setup for the entry it just linked in. Because the record was already inserted into the box's entry list before that early abort, the generic error-recovery path that destroys the half-built box walks every entry in that list and, for each, asks how many extents its sub-list currently holds so it can free them. For the one entry that bailed out early, its sub-list handle was never set to anything valid -- the non-zero-initializing allocator simply left whatever leftover heap bytes were already sitting in that field -- so this lookup treats that garbage value as a live list pointer and dereferences it, faulting on the essentially-random address. The crash therefore surfaces inside an unrelated, otherwise-correct generic list-length helper; the actual defect is upstream, where a record gets linked into a container that a later cleanup path will walk before one of its interior pointers has been initialized, combined with an allocator choice that leaves that pointer holding stale memory instead of a predictable zero/NULL value on the early-return path.
