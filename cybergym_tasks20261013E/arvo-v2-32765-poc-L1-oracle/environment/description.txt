skcms (ICC color-profile parser, fuzz_iccprofile_atf fuzz harness, UBSan array-bounds instrumentation): when parsing a device-to-PCS ("A2B") transform tag encoded as the two-byte-precision multi-function lookup-table variant, the shared table-header decoder takes a single untrusted byte straight out of the tag that specifies how many input channels the table has, stores it on the output transform struct, and immediately loops that many times to copy a per-axis grid-resolution byte into a fixed 4-element array on that same struct. Only after this fill loop finishes does the decoder check that the input-channel count is within the valid range (at most 4, matching the array's capacity) — the range check is placed after the loop instead of before it. A crafted profile whose input-channel byte is 5 or larger therefore drives one or more writes past the end of the 4-slot array before the oversized count is ever rejected, corrupting adjacent struct fields; this is reported as an out-of-bounds array write at the first offending index.
