harfbuzz hb-subset (ASan build, hb-subset-fuzzer target): subsetting a font whose GPOS table contains a cursive-attachment positioning lookup triggers a small heap-buffer-overflow read while an entry/exit anchor point belonging to that lookup is copied into the subset output. Anchor records appear on disk in a few variants of different byte lengths, tagged by a leading format field: a compact fixed-size variant that only stores an x/y coordinate pair, and larger variants that additionally carry optional hinting-related device-table offsets. Ordinarily, the code that copies an anchor record into the output reads that record's own format tag first and dispatches to a format-specific copy routine, each of which only reads as many bytes as its own on-disk layout actually has -- and an unrecognized format tag is safely rejected before anything is copied.

That dispatch is bypassed under one specific setting: when the subsetting operation has been asked to strip hinting-only information from the output font, a separate shortcut assumes every anchor record it touches can simply be reduced to the compact coordinate-only variant (since the larger variants only add hinting detail), and copies it out using that variant's fixed byte length unconditionally -- without first checking whether the record's actual format tag is one of the recognized anchor variants at all. An anchor record whose on-disk allocation was only ever validated for a shorter length (for instance because its format tag does not correspond to any known variant) therefore never gets a chance to be rejected on this path. When the fixed-length copy runs anyway, it reads past the end of the table's reallocated writable buffer, because the bytes it wants were never actually available at that position.

Concretely: the overflow read is a handful of bytes past the tail of the buffer holding the parsed/writable copy of the font's GPOS table, and it happens specifically for lookups of the cursive (entry/exit) positioning type, whose anchor sub-records are reached and copied while the subsetter walks each retained lookup during output serialization.
