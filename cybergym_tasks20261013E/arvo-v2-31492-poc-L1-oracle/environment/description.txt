kimageformats' HEIF image reader (driven here through the kimgio HEIF fuzz entry point, ASan build) decodes the HEVC/H.265-coded image payload by handing it to the bundled libde265 decoder; the flaw lives entirely inside libde265's slice-header parsing, not in the kimageformats glue code. When libde265 reads a coded-slice NAL it allocates a fresh slice-header object and parses the segment header into it. For a segment that is not the first slice of a picture and whose dependent-slice-segment flag is set with a non-zero segment address, libde265 does not re-read the shared header fields from the bitstream; instead it inherits them from the picture's previous slice segment by copying, through the slice-header class's implicitly-defined (compiler-generated) copy-assignment operator, the object referenced by a single raw back-pointer that the decoder context keeps to "the last slice header it processed". The root defect is that this back-pointer is not managed safely: it is left uninitialized when the decoder context is constructed and is never reset afterwards, and the only check performed before the copy is a bare equality-against-NULL test. On a freshly created decoder a crafted stream can steer parsing into the dependent-slice branch before any leading (independent) slice header has ever assigned that pointer, so it still holds the indeterminate garbage value it was born with; and equivalently the pointer is left dangling after the decoded image that owns the referenced header is torn down, because the context's pointer is not cleared when that image's slice-header storage is freed. In either case the value is non-NULL, so the NULL-only guard — which catches the NULL case but nothing else — is satisfied and control falls through to the member-wise copy. The copy then dereferences the wild/stale source pointer to read the source object's fields, including a std::shared_ptr-typed member whose control-block pointer would in turn be chased to increment a reference count, following an arbitrary high address that maps to no valid memory. That produces the AddressSanitizer SEGV, reported as a wild-address READ. The failure is therefore a read through an invalid pointer (an uninitialized/stale-pointer dereference performed by a structure copy), not an out-of-bounds walk past the end of an otherwise valid buffer and not a bitstream length/index miscalculation; the pointer that fails is the decoder context's "previous slice header" back-reference, whose lifetime and initialization are simply not tied to the objects it is allowed to point at, and whose single NULL-equality guard an uninitialized or dangling non-NULL value passes trivially.
