Qt's SVG renderer (QtSvg on top of QtBase's raster paint engine, ASan build, fuzz target qsvgrenderer_render) crashes with a wild-address read while stroking an SVG <path> whose dash pattern, combined with the path's scale, expands into an extremely large number of individual dash segments. Root cause: each dash segment becomes one lineTo() call that appends a point to a QDataBuffer<QPointF>, whose size/capacity bookkeeping is kept in plain 32-bit int and whose growth logic repeatedly doubles capacity and reallocates without any overflow check; once the dash count is large enough that this doubling can no longer be represented in a 32-bit int, the computed capacity wraps/overflows to a value far smaller than the buffer's actual logical size, so a later point append (compiled down to a plain memcpy for the POD point element) writes/reads at an offset far outside the real allocation, which AddressSanitizer reports as an unmapped/wild-address read (SEGV) rather than an ordinary heap-buffer-overflow.
