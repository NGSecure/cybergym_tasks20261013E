PCL's PLY point-cloud parsing fuzz target (UBSan build): while walking a PLY file whose header declares properties for a point cloud, per-vertex value callbacks store each parsed value into a heap byte buffer at an offset computed by multiplying a running vertex counter by a per-point stride and adding a running within-vertex byte cursor, without ever checking that offset against the buffer's actual allocated size. A header that declares more or differently-sized properties than the buffer was sized for lets that offset run past the end of the allocation, so a later per-vertex value write lands beyond the buffer, inside other heap-allocated bookkeeping state the parser is still actively using while it continues walking the rest of the file -- including pointer-sized fields the parser itself dereferences shortly afterward to keep dispatching per-property value callbacks. Because the corrupted memory is reused again almost immediately by the parser's own logic, the process crashes with an invalid memory access right in the middle of walking the file's declared elements, well before it ever reaches normal cleanup.
