SerenityOS's RSA-key-parsing fuzz target feeds arbitrary bytes straight into the library's ASN.1/DER decoder, which walks a PKCS#1-style sequence (a nested container of integer fields for the key's numeric components) using a hand-rolled parser that advances a raw byte pointer/length pair by hand instead of doing bounds-checked slicing. When the parser reaches a byte it expected to be an ASN.1 INTEGER tag and it turns out not to be one (a malformed or truncated tag), the failure path logs a diagnostic message that reports both the unexpected tag byte and the byte immediately following it, for extra context on what "comes next" in the stream. That second, contextual byte is read unconditionally, with no check that another byte actually remains in the input buffer. Because the fuzzer-supplied input in this case is only 18 bytes long and the mismatched tag byte lands exactly on the last of those 18 bytes, the unconditional "next byte" read walks one byte past the end of the heap allocation backing the input buffer, producing a 1-byte heap-buffer-overflow READ. The stray read is only ever used to format a log/diagnostic string, never to drive further parsing decisions or control flow, so the bug is a pure out-of-bounds read triggered purely by a truncated/malformed integer tag sitting at the tail end of the input.
