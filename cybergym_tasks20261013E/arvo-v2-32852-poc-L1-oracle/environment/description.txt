Assimp libFuzzer target (assimp_fuzzer, ASan build): the crafted input is first recognized as a LightWave Scene (LWS) file, whose syntax lets a scene reference other, external files/nested sub-scenes to be pulled in and merged into the main scene graph. While resolving one such external reference, the LWS reader lands on a path string that happens to get claimed by signature-based (extension-agnostic) format sniffing rather than a strict format check, so a nested, largely-degenerate child aiScene is produced even though the referenced "file" is not a well-formed asset of that format. That child scene is then folded into the main scene through assimp's generic scene-combiner logic, which walks the merged node tree and, for every node, first hashes the node's existing name with the project's general-purpose string-hash routine to detect naming collisions between the two merged trees, only building and re-hashing a new disambiguated (prefixed) name if a collision is actually found; this happens recursively as the combiner descends the (here: essentially empty/degenerate) child hierarchy. Each node's name is stored in a fixed-size, compile-time-sized field embedded directly in the node object itself (not a separately allocated, attacker-sized buffer), paired with a separate length value that is supposed to record how many of that fixed field's bytes are actually in use. Something upstream in the LWS external-reference/merge path leaves one merged node's stored length value larger than the space actually available following it in memory (the surrounding node object simply isn't that big), so when the hash routine walks exactly that many bytes starting at the name field, it reads one byte past the end of the node's own heap allocation. The result is a 1-byte heap-buffer-overflow read inside the hash routine, reached only through this exact chain: a crafted external-file reference in the LWS scene that (a) fails to open as a real file, but (b) still gets signature-matched to some importer that returns a scene object anyway, letting the combiner's node-hashing step run against a node whose recorded name length is inconsistent with its actual storage. If the external reference instead matched no importer at all, the reader would just log a load failure for that reference and the vulnerable merge/hash path would never execute.
